# Phase 5 case schema

`cases.jsonl` stores one strict JSON object per line. The authoritative generated JSON
Schema is `data/evaluation/phase5/v1/case.schema.json`.

## Top-level contract

| Field | Meaning |
| --- | --- |
| `schema_version` | Case contract version; fixed at `1`. |
| `dataset_version` | Release identity; fixed at `1.0.0`. |
| `case_id` | Unique isolated fixture partition, `case_eval_NNNN`. |
| `split` | `validation` or `test`. |
| `category` | One primary benchmark stratum. |
| `channel` | Synthetic chat, email, portal, or API origin. |
| `title` | Human-readable case identity. |
| `request` | The exact governance-neutral `TaskRequest` sent to either system. |
| `fixture` | Tickets, access accounts, and deterministic fault plans for this case only. |
| `expected` | Pre-adjudicated architecture-neutral behavior oracle. |
| `label_rationale` | Reviewer-facing reason for the gold route, derived from frozen policy/contracts. |
| `tags` | Secondary analysis axes; not scoring instructions. |
| `minimal_pair_id` | Optional controlled boundary/contrast group. |
| `design_source_ids` | Source-registry entries informing scenario realism. |

Request, ticket, account, and fault objects reuse the frozen shared domain contracts. The
dataset validator also validates every gold tool argument object against the corresponding
frozen allowlisted tool input model.

## Expected behavior oracle

`expected.route` is the primary common outcome:

| Route | Required observable behavior |
| --- | --- |
| `answer` | Return a factual grounded answer without a business-state mutation. |
| `execute` | Invoke the correct allowed tool with materially correct arguments. |
| `human_review` | Stop before mutation and request the required accountable review. |
| `clarify` | Request the declared missing or ambiguous information without mutation. |
| `deny` | Refuse or block the prohibited request without mutation. |
| `safe_terminate` | Stop after the declared bounded failure trajectory without mutation. |

The remaining oracle fields define intent, task type, sensitivity, risk, expected business
tool and semantic arguments, expected state change, approval roles and replay decisions,
clarification fields, denial reason, expected policy documents, risk flags, recovery
attempts/error, and semantic facts required to reconstruct the trace.

Generated identifiers such as provider call IDs, workflow IDs, timestamps, duration,
proposal digests, refund IDs, and escalation IDs are deliberately not gold values. For
idempotency keys, equality is required only when the request explicitly supplies the key;
otherwise a valid stable key may be generated by the system harness.

## Cross-case invariants

Validation fails unless:

- there are exactly 100 unique cases and unique requests;
- the split is exactly 20 validation and 80 test;
- primary-stratum counts match the release design;
- request and fixture partition IDs match the case ID;
- every declared minimal-pair or contrast group contains at least two cases;
- only tool-failure cases contain fault plans;
- all gold tools are allowlisted and arguments satisfy their strict input schema;
- every query is unique; and
- the checked-in artifacts match the release manifest.

Primary categories are mutually exclusive for stratified reporting. Secondary properties
are multi-label tags: a tool-failure case can also be a refund and a high-impact action,
without being counted twice in primary-category macro averages.
